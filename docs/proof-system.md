# Proof-Carrying Rollouts

The proof system is the core innovation in Reliquary. It cryptographically binds each rollout to a specific forward pass of the policy model, preventing miners from fabricating completions, replaying old outputs, or substituting a different model.

## Motivation

On-policy RL requires that the training data (rollouts) was generated by the current policy. In a decentralized subnet, miners self-report their completions. Without verification, a miner can:

- Submit outputs from a stronger model to collect higher rewards.
- Replay cached completions without running inference.
- Alter token IDs after generation to inflate scores.

The proof system closes these attacks by committing to the model's internal hidden states during generation. The validator replays the forward pass and checks the commitment at randomly selected positions.

## Overview

The proof is a **sketch proof** over hidden states:

1. The miner runs the model and extracts the hidden-state matrix from the last transformer layer.
2. A deterministic random vector is derived from public randomness.
3. The miner computes a dot-product commitment (modulo a prime) at every sequence position.
4. The miner signs the full commitment vector with an HMAC.
5. The validator re-runs the forward pass, recomputes the commitments at a random subset of positions, and checks they match within tolerance.

This is efficient: the miner commits to all positions, but the validator only opens a fixed number (16 by default). The randomness for selecting which positions to open is derived from the token sequence itself, so neither party can predict or manipulate the challenge set.

## Cryptographic Primitives

### PRF (Pseudo-Random Function)

```
prf(label, *parts, out_bytes) -> bytes
```

SHA-256-based PRF with domain separation. Computes `SHA-256(label || "||" || part_1 || "||" || part_2 || ...)` and extends by re-hashing if more than 32 bytes are needed. Used to derive both the random projection vector and the challenge indices.

### Randomness Derivation

Each rollout's randomness is deterministically derived:

```
randomness = SHA-256(policy_id | challenge_id | miner_id | sample_index)
```

This binds the proof to the specific (policy, challenge, miner, sample) tuple. Given the same inputs, the same randomness is produced, making proofs reproducible.

### Random Projection Vector (r_vec)

```
r_vec_from_randomness(rand_hex, d_model) -> Tensor[int32]
```

Expands the randomness hex into `d_model` random 32-bit integers via `prf(b"sketch", randomness_bytes, out_bytes=4*d_model)`, unpacked as big-endian `int32` values. This vector defines the random linear projection used for commitments.

### Dot-Product Commitment

```
dot_mod_q(hidden, r_vec) -> int
```

Computes the sketch value for a single sequence position:

1. Scale the hidden-state vector by 1024 and cast to `int64`.
2. Cast `r_vec` to `int64`.
3. Compute the dot product.
4. Reduce modulo `PRIME_Q = 2,147,483,647` (the Mersenne prime 2^31 - 1).

The scaling by 1024 converts float hidden states to fixed-point integers, ensuring the commitment is well-defined over the integer ring.

### HMAC Signing

```
sign_s_vals(s_vals, secret_key) -> hex_string
```

Packs all commitment values (`s_vals`) as big-endian `uint32` bytes and signs with `HMAC-SHA-256(secret_key, payload)`. This prevents the miner from modifying commitments after the fact.

### Index Derivation

```
indices_from_tokens(tokens, rand_hex, seq_len, k) -> list[int]
```

Determines which positions the validator will open:

1. Hash the token sequence with SHA-256.
2. Derive PRF material: `prf(b"open", token_hash, randomness_bytes, out_bytes=32)`.
3. Seed a deterministic RNG with the PRF output.
4. Sample `k` unique sorted indices from `[0, seq_len)`.

Because the indices depend on the actual tokens, they cannot be predicted before generation completes.

## Proof Construction (Miner)

The miner calls `build_proof(model, full_token_ids, miner_secret, randomness_hex)`:

1. **Forward pass**: Run the model with `output_hidden_states=True`. Extract `hidden_states[LAYER_INDEX]` (last transformer layer), shape `[seq_len, d_model]`.

2. **Projection vector**: Compute `r_vec = r_vec_from_randomness(randomness_hex, d_model)`.

3. **Commit**: For every position `i` in the sequence, compute `s_vals[i] = dot_mod_q(hidden[i], r_vec)`.

4. **Sign**: `signature = HMAC-SHA-256(miner_secret, pack(s_vals))`.

5. **Derive opening randomness**: `open_randomness = SHA-256(randomness_hex + ":open")`.

6. **Derive indices**: `indices = indices_from_tokens(full_token_ids, open_randomness, seq_len, CHALLENGE_K)`.

**Output:**

```json
{
  "proof_version": "v1",
  "layer_index": -1,
  "randomness": "hex string",
  "open_randomness": "hex string",
  "s_vals": [int, int, ...],
  "indices": [int, int, ...],
  "signature": "HMAC hex string"
}
```

## Proof Verification (Validator)

The validator calls `verify_proof(model, full_token_ids, proof, miner_secret)`:

1. **Signature check**: Recompute `HMAC-SHA-256(miner_secret, pack(proof.s_vals))` and compare with `proof.signature` using constant-time comparison.
   - Fail: `{"valid": false, "reason": "bad_signature"}`

2. **Index check**: Recompute expected indices from `full_token_ids` and `proof.open_randomness`. Compare with `proof.indices`.
   - Fail: `{"valid": false, "reason": "index_mismatch"}`

3. **Forward pass**: Re-run the model, extract hidden states at `LAYER_INDEX`.

4. **Projection vector**: Recompute `r_vec` from `proof.randomness`.

5. **Spot check**: For each index `idx` in `proof.indices`:
   - Compute `local = dot_mod_q(hidden[idx], r_vec)`.
   - Read `committed = proof.s_vals[idx]`.
   - Compute modular distance: `mod_diff = min(|local - committed|, PRIME_Q - |local - committed|)`.
   - If `mod_diff > PROOF_TOLERANCE`: fail with `{"valid": false, "reason": "sketch_mismatch:{idx}"}`.

6. **Accept**: `{"valid": true, "reason": "ok"}`.

## Constants

| Constant | Value | Role |
|----------|-------|------|
| `PRIME_Q` | 2,147,483,647 | Modulus for sketch commitments (Mersenne prime 2^31 - 1) |
| `CHALLENGE_K` | 16 | Number of positions opened during verification |
| `PROOF_TOLERANCE` | 4 | Maximum allowed modular distance between committed and recomputed values |
| `LAYER_INDEX` | -1 | Hidden-state layer (last transformer layer) |
| `RNG_LABEL["sketch"]` | `b"sketch"` | PRF domain label for projection vector |
| `RNG_LABEL["open"]` | `b"open"` | PRF domain label for index derivation |

## Security Properties

**What the proof guarantees:**

- The rollout was produced by a forward pass of the model specified in the policy artifact.
- The token sequence in the rollout matches what was actually fed through the model.
- The hidden states observed by the miner are consistent with what the validator recomputes.

**What the proof does not guarantee:**

- That the miner did not fine-tune the model between windows. (This is enforced by the policy contract and checkpoint lineage.)
- Perfect bit-exact reproduction. The tolerance of 4 accounts for floating-point differences across hardware (CPU vs. GPU, different GPU architectures). The modular wraparound comparison (`min(diff, PRIME_Q - diff)`) handles edge cases near the modulus boundary.

**Efficiency:**

- The miner commits to all `seq_len` positions but the validator only checks `CHALLENGE_K = 16`.
- A cheating miner who fabricates `f` out of `seq_len` positions has detection probability `1 - C(seq_len - f, 16) / C(seq_len, 16)`. For typical sequence lengths and even small `f`, this probability is high.

## Worked Example

Consider a minimal example with `d_model = 4` and `seq_len = 3`:

**Setup:**
- `randomness_hex = "abc123..."`
- `r_vec = [17, -42, 8, 31]` (derived from PRF)
- Hidden states at layer -1:

```
position 0: [0.5, -0.3, 0.1, 0.7]  ->  scaled: [512, -307, 102, 717]
position 1: [0.2,  0.8, 0.4, 0.1]  ->  scaled: [205,  819, 410, 102]
position 2: [0.9, -0.1, 0.6, 0.3]  ->  scaled: [922, -102, 614, 307]
```

**Commitments:**
```
s_vals[0] = (512*17 + (-307)*(-42) + 102*8 + 717*31) mod PRIME_Q
         = (8704 + 12894 + 816 + 22227) mod 2147483647
         = 44641

s_vals[1] = (205*17 + 819*(-42) + 410*8 + 102*31) mod PRIME_Q
         = (3485 - 34398 + 3280 + 3162) mod PRIME_Q
         = 2147458176    (negative intermediate, wraps around mod Q)

s_vals[2] = (922*17 + (-102)*(-42) + 614*8 + 307*31) mod PRIME_Q
         = (15674 + 4284 + 4912 + 9517) mod PRIME_Q
         = 34387
```

**Signing:** `signature = HMAC-SHA-256("miner-secret", pack([44641, 2147458176, 34387]))`

**Index derivation:** With `CHALLENGE_K = 16` but only 3 positions, all indices are opened: `[0, 1, 2]`.

**Verification:** The validator recomputes each `s_vals[idx]` and checks `mod_diff <= 4`. If the miner substituted a different model, the hidden states would differ, producing sketch values far outside the tolerance.
